Fonctionnement du projet LLM_NETFLIX
====================================

1. Objectif
-----------
LLM_NETFLIX est une plateforme locale de question-reponse sur le catalogue
Netflix contenu dans `data/netflix_titles.csv`.

Le projet combine deux approches :

1. RAG avec ChromaDB pour les questions descriptives ou semantiques.
2. NL2SQL avec PostgreSQL pour les recherches structurees et les listes.

Le chatbot, la CLI, l'API et l'interface Streamlit repondent en anglais.


2. Technologies utilisees
-------------------------
- Python et uv
- LangChain
- Ollama avec `llama3.2:1b`
- Ollama embeddings avec `nomic-embed-text`
- ChromaDB persistant dans `chroma_db/`
- PostgreSQL avec la base `netflix_db`
- SQLAlchemy pour charger et interroger PostgreSQL
- FastAPI pour le backend
- JWT avec `python-jose`
- WebSocket pour une diffusion simplifiee des reponses
- Streamlit pour l'interface web
- Plotly pour les visualisations
- Scikit-learn pour le baseline de routage experimental
- pytest et httpx pour les tests
- Dockerfile et docker-compose pour le deploiement


3. Donnees
----------
Le dataset est :

data/netflix_titles.csv

Il contient 8 807 titres Netflix. Le fichier CSV ne doit jamais etre modifie.

Colonnes principales :
- show_id
- type
- title
- director
- cast
- country
- date_added
- release_year
- rating
- duration
- listed_in
- description


4. Ingestion ChromaDB
---------------------
Le fichier `src/ingest.py` prepare la base vectorielle ChromaDB.

Etapes :
1. Lire `data/netflix_titles.csv`.
2. Remplacer les valeurs manquantes uniquement dans `director`, `cast`,
   `country` et `date_added` par `Inconnu`.
3. Construire un document texte par titre avec le template impose.
4. Generer les embeddings avec `nomic-embed-text` via Ollama.
5. Stocker les documents dans `chroma_db/`, collection `netflix_catalog`.

Commande :

uv run python src/ingest.py


5. Chargement PostgreSQL
------------------------
Le fichier `src/load_postgres.py` charge le CSV dans PostgreSQL.

La base utilisee est `netflix_db` et la table est `netflix_titles`.
Le projet utilise `DATABASE_URL` depuis `.env`.

Commande :

uv run python src/load_postgres.py


6. Routage RAG + NL2SQL
-----------------------
Le fichier `src/router.py` classe les questions en intentions :
- rag
- sql
- mixed
- visualization

Le fichier `src/nl2sql.py` transforme les questions structurees en requetes SQL
securisees. Il autorise uniquement les requetes SELECT et bloque les operations
dangereuses comme DROP, DELETE, UPDATE, INSERT, ALTER ou TRUNCATE.

Le fichier `src/retriever.py` garde le fallback ChromaDB/Python, notamment pour
les cas ou PostgreSQL ne trouve pas de resultat a cause d'accents ou de variantes
textuelles.


7. Chaine de reponse
--------------------
Le fichier `src/chain.py` orchestre le pipeline :
1. Nettoyage et resolution simple des questions de suivi.
2. Tentative NL2SQL si la question est structuree.
3. Fallback RAG/ChromaDB si necessaire.
4. Reponse finale en anglais, en langage naturel.

Le prompt systeme impose :
- repondre en anglais ;
- ne jamais retourner de CSV, JSON, tableau Markdown ou liste brute ;
- mentionner tous les titres pertinents trouves dans le contexte.


8. Interfaces
-------------
CLI :

uv run python src/app.py

Streamlit :

uv run streamlit run src/web_app.py

FastAPI :

uv run uvicorn src.backend.main:app --reload

Endpoints principaux :
- GET /health
- POST /token
- POST /chat
- GET /history
- POST /feedback
- GET /stats
- WS /ws/{session_id}


9. Evaluation et tests
----------------------
Tests automatises :

uv run pytest tests/ -v

Validation manuelle realisee :
- 50 prompts varies testes
- 50 reussites
- 0 echec

La suite pytest actuelle passe avec 20 tests.

Le script `evaluation/evaluate.py` exporte :
- exports/evaluation_results.csv
- exports/netflix_stats.csv

Ces fichiers peuvent etre ouverts dans Power BI.


10. Limites connues
-------------------
- `llama3.2:1b` est leger et peut etre moins fiable sur des questions tres
  ambigues.
- Les grandes listes produisent volontairement des reponses longues, car le
  systeme doit mentionner tous les titres pertinents.
- React.js est documente comme perspective dans `frontend/README.md`, mais pas
  implemente comme application complete.
- Le WebSocket diffuse la reponse apres generation ; ce n'est pas encore un vrai
  streaming natif token par token depuis Ollama.
- Ollama doit etre lance localement avant d'utiliser les fonctions RAG.
